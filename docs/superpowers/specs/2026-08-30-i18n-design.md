# 多言語化（i18n）設計書

- 日付: 2026-08-30
- 状態: ユーザー承認済み（チャットで設計合意。Rust メッセージは英語に統一 = 案 A）
- 前提: TuneR / YTDown（`/Volumes/Logitec2/work/TuneR`, `/Volumes/Logitec2/work/YTDown`）と同じ流儀。キー命名は YTDown 式（ネスト）
- 実装順: v1.1 §2（背景色）マージ後に単独ブランチ `feature/i18n` で 1 本の PR。その後に v1.1 §3 / §4

## 1. 目的と範囲

- UI の全文字列を 8 言語（`ja`, `en`, `de`, `es`, `fr`, `ko`, `pt-BR`, `zh-TW`）に対応させる
- Rust（Tauri コマンド）が返すエラー／結果の文言は **英語に統一**し、フロントはそのまま表示する（YTDown と同じ割り切り。翻訳はしない）
- Chrome に注入する手動操作オーバーレイの文言（「録画開始」「撮影開始」「中止」「操作可能になりました…」「録画中… 残り N 秒」「保存処理中…」「録画・保存中… 残り N 秒 (M コマ完了)」）は **フロントで翻訳した文字列を引数で Rust に渡す**。Rust は翻訳表を持たない
- 対象外: README / AGENTS.md / 設計書（英語併記済み）、アプリ名 "ResponsiveShot"、Chrome のページ内容

## 2. 構成

- 依存追加: `vue-i18n@^11`（TuneR / YTDown と同じ。**新規依存はこれ 1 つ**）
- `src/i18n/index.ts`
  - `SUPPORTED_LOCALES = ['ja', 'en', 'de', 'es', 'fr', 'ko', 'pt-BR', 'zh-TW'] as const`、表示名 `LOCALE_NAMES`（各言語の自称: 日本語 / English / Deutsch / Español / Français / 한국어 / Português (Brasil) / 繁體中文）
  - `detectLocale()`: `localStorage.getItem('responsiveshot_language')` が対応言語ならそれ → `navigator.language` の先頭一致（`ja`→ja, `zh`→zh-TW, `pt`→pt-BR, `ko`, `fr`, `es`, `de`, `en`）→ 既定 `en`
  - `createI18n({ legacy: false, locale: detectLocale(), fallbackLocale: 'en', messages })`
  - `setLocale(locale)`: `i18n.global.locale.value` 更新 + `localStorage.setItem('responsiveshot_language', locale)` + `document.documentElement.lang = locale`
- `src/locales/<locale>.json`: 8 ファイル、**全ファイルでキー集合が同一**（`scripts/check-locales.mjs` で検証し `pnpm test` に組み込む）
- `src/main.ts` で `app.use(i18n)`
- コンポーネントは `const { t } = useI18n()` → `t('section.key')`。テンプレートで `$t` は使わない

- ヘッダー右上の System / Light / Dark セレクトの左隣に言語セレクト（`<select>`、`LOCALE_NAMES` を表示、`@change` で `setLocale`）

## 5. Rust 側の変更（案 A）

- `src-tauri/src` の非テストコードにあるユーザー向け日本語文字列をすべて英語にする。対象は `Err(...)` / `format!(...)` / `ok_or_else(...)` の文言: `main.rs`（中止・保存先作成・スレッド失敗・スクショ読込・PNG エンコード・フレーム読込）、`frames/catalog.rs`（読込失敗・id 重複・id 文字種・vendor・category・screen 範囲・pattern）、`frames/compose.rs`（背景色）、`frames/store.rs`（色未選択・フレーム未検出・読込失敗・寸法不一致）、`frames/import.rs`（寸法不一致・画像読込・保存先作成・コピー失敗・DMG マウント失敗の案内・hdiutil 起動失敗・取り込み元なし）、`frames/targets.rs`（PNG のみ・カタログ未読込・不明デバイス）
- 英訳の指針: 名詞句 + コロン + 詳細。例: `Frame not found: iPhone 16 Pro (black-titanium). Import the frames again.` / `Frame image size mismatch (expected 1350x2760, got 10x10): <path>. Import the frames again.` / `Device frames support PNG output only` / `Invalid background color: "…" (use #rrggbb)` / `Failed to mount the DMG: <stderr>. If it is already mounted in Finder, eject it first, or use "Import folder" and pick the volume under /Volumes`
- テスト内の日本語アサーション（`contains("重複")` 等）は英語の部分文字列に更新する。テスト名・コメントの日本語は変更しない
- `capture_screenshots` に `overlay: OverlayLabels` を追加（`#[derive(Deserialize)] struct OverlayLabels { start, cancel, intro, ready, recording, saving, progress: String }`）。`recording` / `progress` は `{seconds}` / `{frames}` をフロント側で埋めずにテンプレートとして渡し、Rust が `.replace("{seconds}", …)` で埋める。注入 JS への埋め込みはシングルクォートと `\` をエスケープしてから行う（XSS/構文崩れ防止。既存の `textContent` 方針は維持）
- `select_element` が注入する要素選択 UI にも文言があれば同様に `overlay` 相当を渡す（計画時に確認）

## 6. 翻訳

- `ja` と `en` は現行 UI の文言を正として用意。他 6 言語は同じキー集合で私（Claude）が翻訳し、PR 本文に「機械翻訳ベース、要ネイティブ確認」と明記する
